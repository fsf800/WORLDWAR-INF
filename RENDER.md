# Render deployment (vanilla OpenFront)

This fork keeps the upstream OpenFront game code unchanged. `render.yaml` only supplies the runtime configuration needed to run the existing upstream Docker image layout on Render.

## Deploy

1. Open Render Dashboard.
2. Choose **New → Blueprint**.
3. Select `fsf800/WORLDWAR-INF`.
4. Confirm the service is named `worldwar-inf` and the instance type is **Free**.
5. Deploy.

If the Blueprint already exists, open it and click **Manual sync** after changes to `render.yaml`.

If the web service already exists, wait for the new deploy to become **Live**. If Render does not redeploy automatically, open the service's **Deploys** page and manually deploy the latest commit.

## Why `CDN_BASE` is configured

OpenFront runs the game simulation in an inline `blob:` Web Worker. On a self-hosted deployment, the worker needs absolute URLs for hashed map assets under `/_assets`. The Blueprint maps `CDN_BASE` to Render's automatically assigned `RENDER_EXTERNAL_URL`, so the existing OpenFront asset URL machinery produces same-origin absolute URLs without changing gameplay code.

## Runtime settings

- Dockerfile: upstream `./Dockerfile`
- Public HTTP port: `80` (upstream nginx)
- Health check: `/api/health`
- Workers: `1` for the free instance
- Game environment: `dev`, matching upstream's local self-host configuration
- Turnstile: Cloudflare test site key used by upstream local development

`API_KEY` and `ADMIN_BOT_API_KEY` are generated by Render and are not stored in Git.

## Notes

This is intended for a small private/hobby server, not the official OpenFront production infrastructure. Account/subscription features that depend on OpenFront's separate production API are not part of this one-service Render setup.
